## PRE-CHANGE FACTS

- `WorktreeService.cleanup()` je nakon identity match-a koristio originalni caller
  `worktree_path` i za `get_status(...)` i za `git worktree remove <path>`.
- `can_cleanup()` je vraćao samo `(bool, reason)`, odbacujući matched `WorktreeInfo`,
  pa `cleanup()` nije imao pristup registrovanom `WorktreeInfo.path`.
- Rezultat: relativan caller input (`worktrees/RELATIVE`) je canonicalizovan do tačnog
  matcha, ali je `_git()` relativni string izvršavao iz `self._repo`, što može ciljati
  drugi target (npr. `A/repo/worktrees/RELATIVE` umjesto `A/worktrees/RELATIVE`).

## IMPLEMENTATION

### Matched path authority

- Novi interni helper `WorktreeService._resolve_cleanup_target(worktree_path) ->
  tuple[WorktreeInfo | None, str]` vraća matched candidate i prazan razlog kada je
  cleanup dozvoljen.
- Hard guards ostaju u helperu: unknown (`None`), main/unmanaged (`is_main`), conflict
  (`get_status(...).has_conflicts`).
- `can_cleanup()` zadržava javni potpis `(worktree_path) -> tuple[bool, str]` i sada
  delegira helperu.
- `cleanup()` koristi isti helper i za status (`get_status(info.path)`) i za
  destructive remove (`git worktree remove info.path`) — matched canonical path, ne
  originalni caller input.

### Force semantics

- Nepromenjeno u odnosu na FLOW-1110: `force=True` dodaje `--force` git flagu, ali ne
  zaobilazi unknown/unmanaged/main/project identity/conflict niti menja destructive
  target.

### Project binding

- Nije mijenjan. Manager i dalje vezuje `WorktreeService` za `Project.repo_path`.
